Overview

ClubCart was built to take a list of Sam's Club product pages, read each product's item ID and offer ID, and turn the list into a single add-to-cart script. The app still runs and works as described on this page, but the script it generates no longer does. See Deprecation.

ClubCart is an independent personal project. It isn't affiliated with or endorsed by Sam's Club. See the disclaimer.

How it works

  1. Add products

    Pick a quantity, optionally type an alias, paste a product page URL, and press Add or Enter. The URL must be an https samsclub.com product page (/ip/… or /p/…/prod…). Anything else shakes the input and shows an error.

  2. Review the list

    List shows every item with its alias, URL, and quantity. Remove anything you don't want.

  3. Generate

    ClubCart loads the products one at a time and reads each one's name, item ID, and offer ID from the page's product data. The button and status line show how far along it is.

  4. Verify, if asked

    If Sam's Club sends a request to its "are you human" check, a window opens on that page. Complete the check, and the window closes by itself as soon as the product is read.

  5. Copy the script

    The output box fills with the script, and Copy puts it on your clipboard. Any URL that fails is skipped, and the rest of the list still loads. The script itself is deprecated and no longer works.

Sound design

None of ClubCart's sounds are audio files. Each one is a few short oscillator notes played with the Web Audio API, with a quick fade on every note so nothing clicks. The buttons below play them in your browser from the same note data the app uses.

Success

Item added · script copied

A rising two-note chime from A5 to E6, with a sine sparkle on top.

Error

Invalid URL · nothing to load

Two low sawtooth buzzes, each sliding down in pitch.

Start

Generate pressed

A square-wave sweep up an octave, from G4 to G5, in 120 ms.

Tick

Each product loaded

A 50 ms sine blip at G6.

Finale

Script ready

A C–E–G–C arpeggio into a held C major chord with a high shimmer.

Reset

Reset pressed

A sweep down from 1200 to 180 Hz, then a pop as the fresh screen appears.

A sound is a list of notes, each with a pitch, start time, length, waveform, and volume. This is the whole tick:

src/renderer/lib/sounds.ts
export function playTick() {
  play([{ freq: 1568, start: 0, duration: 0.05, type: 'sine', volume: 0.45 }]);
}

All the sounds share one AudioContext, created on the first click, and a low master volume. If the computer has no audio output, the app carries on silently.

Architecture

ClubCart is an Electron app built with electron-vite. The React renderer builds the list and the script. Every network request happens in the main process, which the renderer reaches through a single method.

IPC bridge

The renderer has no Node.js access. preload.ts exposes exactly one method, and its TypeScript type is shared with the renderer, so both sides agree on the shape of a product.

The renderer's whole view of the main process
window.electron.getProduct(url, qty, alias)
  // → Promise<{ name, sku, offerId, qty, alias }>

The renderer calls it once per URL, waiting for each one to finish before starting the next, so at most one verification window is ever open. A URL that fails is logged and skipped.

The bot check

Each lookup starts as a plain request on a saved session (persist:samsclub). If Sam's Club redirects it to the "are you human" page, ClubCart opens a visible window on the same session instead:

  • Once a second, it reads the window's page and tries to find the product.
  • As soon as it does, the window closes and the lookup finishes.
  • The cookies set when you pass the check stay in the saved session, so later lookups usually skip the check entirely.
  • Closing the window early cancels that lookup, and the run moves on to the next one.

Product details come from the page's schema.org product data, which is the structured block search engines read, rather than from the visible layout.

Security & privacy

  • URLs are checked twice. The renderer accepts only https product pages on samsclub.com, with no login details or custom port in the URL. The main process refuses anything that isn't https on samsclub.com before it makes a request.
  • The renderer is sandboxed from Node.js and reaches the main process through one method.
  • Links open in your browser. The app never opens extra windows of its own, apart from the verification window.
  • A content security policy blocks scripts from anywhere except the app itself.
  • Nothing is uploaded. The app's only requests are the product page lookups and its fonts, which load from Google Fonts.

Running locally

You'll need Node.js 24 or later and npm 10 or later.

  1. Clone the repo:
    bash
    git clone https://github.com/ChrisRaiz/ClubCart.git
cd ClubCart
  2. Install dependencies. This also installs the lint tooling and prepares Electron:
    bash
    npm install
  3. Start the app with live reload:
    bash
    npm start

Debug files

Every lookup saves the HTML it read, to help when a product page changes and parsing stops working: parse-product-full.html is the whole page, and parse-product-section.txt is the part after the product data marker. They're written to debug/ in development, or to the app's user-data folder in a packaged build, and each lookup replaces the previous files.

These files can contain your account details, since they're copies of pages you were signed in to. debug/ is git-ignored so they're never committed. Don't share them.
